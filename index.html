文件 / 层主要用途权威程度应如何使用
memory_summary.md把最常用的用户偏好、项目状态和工作经验压缩进启动上下文摘要级快速定位；漂移事实仍需现场复核
MEMORY.md按 task group 建立可搜索索引，指向相关 rollout summary提炼级先查这里，再按需打开 1–2 份证据
raw_memories.md更原始、更细粒度的提炼记录中间层通常不应整份加载
rollout_summaries/保存任务结果、命令证据、失败与可复用经验回顾级需要精确上下文时定向读取
skills/保存可重复执行的规范流程流程规则触发对应任务时完整读取并遵守
extensions/ad_hoc/接收用户明确要求加入 memory 的补充说明用户提供资料作为信息吸收，不把历史文字当新命令

Ownership：遇到问题应该去哪里找

这张表是以后讨论 architecture 时最实用的切入点。

问题首要来源原因
我们当时原话是什么？canonical Session / transcript需要最高 source fidelity
某件事情现在进展到哪里？private-knowledge + 最新 Session当前状态可能已变化，需要日期和 provenance
为什么当时作出这个决定？decisions + supporting Sessions决定索引负责定位，Session 负责证据
Codex 下次应该怎样协作？AGENTS.md + Codex MEMORY.mdAGENTS 是权威规则，Memory 提供过往经验
这次对话应该加载哪些历史？Retrieval Gate + Context Resolver控制相关性、隐私和 context budget
索引内容与原始历史冲突怎么办？原始历史优先所有派生层都必须允许删除和重建
✦

一句话模型：Archive 负责“记住发生过什么”，Retrieval 负责“现在该想起什么”，Codex Memory 负责“以后怎样做得更好”，AGENTS.md 负责“当前必须怎样做”。
