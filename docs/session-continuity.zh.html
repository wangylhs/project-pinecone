Codex 套件 · 两个手动命令

知道你离开了多久，从上次停下的地方接着聊。

Agent 分不清一分钟和一整夜，新 Session 也总是从零开始。离开一夜回来说一句“早上好”，它会当作一分钟前的延续来回答。开一个新 Session，刚才的梗、情绪、说好要继续的事，都要重新讲一遍才接得上。

$time-sync · $handoff
测量时间差由宿主测量，agent 从不猜。
交接情绪、未完成的事和共同说法带进下一个 Session。
手动不输入命令，就什么都不会运行。
小两个 hook、两个 skill、标准库 Python，外加测试。

同一个 Session 里，时间差从 transcript 算；全新的 Session 没有上一条消息，$time-sync 就改为带上最近一次 handoff，并附上它写于多久之前。

时间 · 测量

$time-sync

本地时间，以及距离你上一条消息的时间差，根据 transcript 时间戳测量。隔了十个小时说“早上好”，会被理解为回来了，而不是接着刚才。测量失败时 agent 直接说明，不估算。

状态 · 交接

$handoff

离开前，agent 写下情绪、最多两件未完成的事、最多三个共同说法和最后的话题。新 Session 里的下一次 $time-sync 会把它带回来一次。

Agent 看到什么

新 Session 里的第一次 $time-sync，前一晚留过 handoff。这里的例子全部是虚构的。

TemporalSync error=no preceding user message. Do not infer elapsed time.
SessionHandoff source_session=0a0a0a0a-0000-4000-8000-000000000001; written_at=2030-01-02T22:41:07+01:00; age=9h 12m. Host-read packet from a previous Session's $handoff: recorded observations, not verified current state.
## Mood
Tired after the ridge survey, but in good spirits

## Unfinished
- Recalibrate the snow gauge before the next storm

## Phrases
- velvet teapot protocol — the crew's name for boiling water twice at altitude

## Last topic
Where to pitch camp two; ended with good night

Skill 会要求 agent 把这些当作带日期的观察，在合适的时候自然接上，不要复述整份内容。同一个 Session 里之后再发 $time-sync，只多两行。

三步安装

复制两个目录，信任两个 hook，开一个新 Session。

1

复制

把套件里的 .codex/ 和 .agents/ 复制到你的 Git 仓库根目录。如果已经有 .codex/hooks.json，把两个 UserPromptSubmit handler 合并进去。

2

信任 hook

Codex 不会运行新增或被修改过的 hook，直到你审核通过，而且不会报错。在仓库里打开 Codex CLI，接受 Hooks need review，或者运行 /hooks。以后每次改 hooks.json 都要重来一遍。

3

开新 Session

然后就能用了：离开时发 $handoff 晚安，回来时发 $time-sync 早上好。

小包存在 .session-continuity/handoff.md。这个目录第一次写入时会自动生成 .gitignore，情绪笔记不会被意外提交。设置 SESSION_HANDOFF_PATH 可以换位置。在套件目录下运行测试：

python3 -m unittest discover -s tests

每种状态都显式说明

一片空白只意味着 hook 没有运行，所以其他每种结果都会说清楚发生了什么。

注入内容含义
TemporalSync gap=…距离本 Session 上一条消息测出的时间差
TemporalSync error=no preceding user message新 Session：改用 handoff 的 age
SessionHandoff age=…后面跟着小包内容
SessionHandoff later_activity=…handoff 写完之后，这个仓库里还有其他 Codex 对话
SessionHandoff long_gap超过 7 天：跟进未完成的事，不接上次的语气
SessionHandoff omitted小包就是在本 Session 写的，或者本 Session 已经注入过
SessionHandoff unavailable / error没有可用的内容，agent 不能猜
HandoffTarget source_session=…agent 写入小包时使用的 id

设计要点

就算不用 Codex，这些决定也值得借鉴。

测量

宿主测量，agent 不推断

时间差来自 transcript 时间戳。测量失败就报告失败，不估算。

跳过

忽略宿主自己注入的内容

找你的上一条消息时，跳过客户端自己加入的指令、环境信息和 skill 内容。否则第一轮永远测出 0。

分工

模型负责写，宿主负责身份

只有模型能做总结，只有宿主知道 Session id。唯一的写入命令先校验模板再覆盖，坏的小包永远替换不掉好的那份。

一份

热上下文，不是第二套记忆

只有一份、每次覆盖，不进 Git，也不进任何索引。情绪是观察而不是指令；隔得太久，就不接上次的语气。

过滤

前一个文件不等于上一次对话

Codex 的 session 目录里混着其他仓库、subagent 和审核线程。只统计你在本仓库里的线程，并报告“之后还有活动”，而不是断言“没有更新的对话”。

预算

每个 Session 一次，有上限

小包最多 800 字符、每行 160 字符，只在第一次 $time-sync 注入。最坏情况按 UTF-8 字节计算也在 hook 上限以内。

◐

测试覆盖不到的故障：hook 定义一改就不再被信任，Codex 不运行它，但每个脚本手动跑都是通过的。所以安装步骤里专门有信任这一步，其他每种结果也都会显式说明。

局限

这个套件不宣称的事情。

  • 依赖 Codex 的具体实现：hook 事件里的 transcript_path、以 Session id 结尾的 rollout 文件名，以及 session_meta 里的 cwd 和 thread_source 字段。在 macOS 上基于 Codex 0.154（CLI 与 Desktop）开发；其他版本和平台未测试。
  • 必须是 Git 仓库，因为 hook 用 git rev-parse 定位路径。
  • later_activity 比较的是文件修改时间，同一仓库里无关的工作也可能触发。它只说 handoff 可能没覆盖到，不会说得更重。
  • Handoff 只装一个 Session 的热上下文，不是持久记忆，也不代表任何事情现在仍然成立。
  • 这套机制可以迁移到其他 agent 宿主，但 transcript 解析和 hook 约定不能照搬。目前还没有移植。
